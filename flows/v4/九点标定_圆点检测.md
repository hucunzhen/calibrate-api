# 九点标定 · 标定板圆点检测

> 换产品时全流程见 **[../产线视觉标定与主流程.md](../产线视觉标定与主流程.md)**「换产品标定与部署」；本文为 **阶段 3** 专章。日常量产见该文档 **§1**。

**适用流程**：`caliNinePoint.flow.json`（工作目录 **`flows/v4/`**）  
**适用算子**：`detect_calibration_dots`（亮框 ROI + 规则网格 + top-hat 逐格检测）  
**版本说明**：对应**网格检测**算法；若 Vis 上圆点散在金属边框上，多为旧版流程/参数，请使用 v4 **`caliNinePoint.flow.json`** 默认 grid 参数。

---

## 1. 目的与范围

| 项 | 说明 |
|----|------|
| **目的** | 在透视矫正后的标定板图像上自动检测圆点像素坐标，完成九点仿射标定并保存 `calibration_nine_point.json` |
| **输入** | 标定板图像、棋盘内参 JSON、世界坐标九点（mm） |
| **输出** | 像素点序列、仿射变换、可选系统误差报告 |
| **不负责** | 棋盘内参、九点 world（中心+偏移，见 [全流程阶段 2](../产线视觉标定与主流程.md) / **calibSendContour**） |

## 2. 前置条件

### 2.1 文件与数据

- [ ] 流程目录（`flows/v4/`）下存在：
  - `models/calibration_nine_point.bmp`（或改为现场图路径）
  - `chessboard/calibration_result.json`（阶段 1 棋盘内参，供去畸变/透视）
  - `models/world_pos.txt` 或九点标定算子内 `worldPoints` 字符串
- [ ] `models/world_pos.txt` 已由阶段 2（**center + step** → **weld_trajectory_world**）生成。

### 2.2 成像与机械

- [ ] 标定板完整入镜，金属外框可见（用于自动板内 ROI）。
- [ ] 圆点网格清晰；强反光时仍应尽量保证板内 ROI 覆盖全部圆点区域。
- [ ] 圆点检测网格为 **3×3**（九点标定）；若现场板型不同，在算子中改 `gridRows` / `gridCols`（见 §5）。

---

## 3. 流程拓扑（v4）

```
load_image → image_flip(vertical) → intrinsics_undistort_image
    → chessboard_perspective_warp_image → detect_calibration_dots → calibrate
    → adjust_affine_calibration(可选) → save_calibration_result
                              ↘ display（Vis + Points 目视）
```

**要点**：圆点检测接在**透视矫正之后**；不再使用 HALCON 标定板 ShapeModel + Mask 链。

---

## 4. 标准操作步骤

### 4.1 打开流程

1. 启动 **IndustrialVisionTools** → 打开流程页。
2. 加载 **`caliNinePoint.flow.json`**（工作目录 `flows/v4/`）。
3. 若曾打开旧版流程，**关闭后重新加载**，避免节点参数仍为旧默认值（如仅 `morphKernelSize=23` 而无 `gridRows`）。

### 4.2 配置取图

1. 选中 **load_image** 节点。
2. 设置 `filePath`：
   - 调试：保持 `models\calibration_nine_point.bmp`；
   - 现场：改为本次采集图路径（相对 flow 文件目录或绝对路径）。
3. 若使用相机，可将该节点替换为 `camera_snap` 等，并保证下游仍为「翻转 → 去畸变 → 透视」链。

### 4.3 配置内参与透视

1. **intrinsics_undistort_image**：`calibrationJsonFile` = `models\calibration_result.json`（或现场内参路径）。
2. **chessboard_perspective_warp_image**：
   - `viewIndex`、`cols`/`rows`/`squareSizeMm` 与标定棋盘一致；
   - 推荐 `perspectiveOutputFrame=plane`、`perspectiveOutputScale=board_pixels`（与产线 README 一致）。
3. **image_flip**：与现场相机安装方向一致（当前 flow 为 `vertical`）。

### 4.4 配置圆点检测（detect_calibration_dots）

默认推荐（与 flow 一致）：

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| gridRows | 3 | 圆点行数 |
| gridCols | 3 | 圆点列数 |
| gridPitchPx | 0 | 0 = 自动估计点间距 |
| dotContrastMin | 5 | 格内 top-hat 对比度下限 |
| morphKernelSize | 13 | top-hat 核（奇数） |
| centroidWinHalf | 14 | 每格局部搜索半宽 |
| roiXMin~YMax | -1 | 自动亮框板内 ROI |

保存节点参数。

### 4.5 配置九点标定（calibrate）

1. 确认 **ImagePts** 已连接自 `detect_calibration_dots` → **Points**。
2. 确认 **Image** 已连接透视矫正输出（用于显示/质检）。
3. `worldPoints` / `worldPointsFile` 填写 9 个世界坐标（mm），顺序与现场 3×3 布局一致。
4. `pixelPickMode` = **匹配检测点**；`confirmCorrespondence` = **true**（推荐，用于从多圆点中选 9 对）。
5. 可选：`calibrationJsonFile` 指向棋盘 JSON，用于标定对话框中的系统整体误差。

### 4.6 运行与目视

1. **单步或整流程运行**至 `detect_calibration_dots` 完成。
2. 查看 **display** 或算子 **Vis** 输出，合格标准见 §6.1。
3. 继续运行 **calibrate**：
   - 弹出配对对话框时，核对像素点与世界点一一对应（顺序错误会导致标定失败或误差极大）。
4. 需要微调时运行 **adjust_affine_calibration**（`interactiveAdjust=true`）。
5. 运行 **save_calibration_result**，确认生成 `models\calibration_nine_point.json`。

### 4.7 记录

- [ ] 记录：日期、操作人、图像路径、gridRows×gridCols、检出点数、重投影/系统误差摘要。
- [ ] 备份 JSON 至项目约定目录。

## 5. 参数微调（仅当 §6 不合格时）

按顺序调整，**每次只改一项**，改后重新运行圆点检测节点。

| 现象 | 建议操作 |
|------|----------|
| 漏检较多（尤其反光区） | `dotContrastMin` 降至 **4**；或 `morphKernelSize` 改为 **11** / **15** 试 |
| 行列数不对 | 修改 `gridRows` / `gridCols`（九点标定为 **3×3**） |
| 整体偏移、间距不对 | 手动设 `gridPitchPx`（透视图上相邻圆心距，约 **58–66 px**，以 Vis 为准） |
| 边缘误检 | 手动 ROI：设 `roiXMin/YMin/XMax/YMax` 仅框住黑色板面 |
| 板子物理行数少于自动估计 | 固定 `gridRows`、`gridCols`，勿依赖自动行数估计 |

**勿再依赖** `templateCenterX/Y`、`matchThreshold` 等旧模板参数（当前算法未使用）。

---

## 6. 验收标准

### 6.1 圆点检测 Vis

- [ ] 图像上有 **绿色矩形**（板内 ROI）。
- [ ] **蓝色圆环**落在黑色板面圆点上，**不在**金属外框、键盘背景上。
- [ ] 检出 **9/9** 点；`GridRows`×`GridCols` = 3×3。
- [ ] `GridRows` / `GridCols` 输出与参数一致。

### 6.2 九点标定

- [ ] 配对对话框中 9 组点逻辑正确（左→右、上→下与 `worldPoints` 一致）。
- [ ] 重投影误差在项目允许范围内（具体阈值由工艺/质量文件规定）。
- [ ] 保存的 JSON 可被 `load_calibration_result` / `img_to_world` 正常加载。

---

## 7. 异常处理

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 蓝圈贴满金属边框 | 旧 flow / 旧参数 | 重载 v4 **`caliNinePoint.flow.json`**，确认 `gridRows`/`gridCols` |
| 报错 Mask / ShapeModel Row 为空 | 仍在使用 halcon 旧版九点 flow | 改用 v4 目录下 `caliNinePoint.flow.json` |
| `CALIB_DetectCalibrationDots failed` | 找不到板内亮框 | 检查是否过曝/无金属框；或改手动 ROI |
| 检出 0 点 | ROI 过小、对比度门槛过高 | 降 `dotContrastMin`、放大 ROI、检查透视是否失败 |
| 标定误差极大 | 像素/世界点顺序不一致 | 重开配对对话框，按 3×3 物理位置核对 |
| 去畸变/透视图异常 | 内参 JSON 错误或 viewIndex 不对 | 先单独跑棋盘流程验证 JSON |

## 8. 与旧方案差异（培训要点）

| 旧方案 | 现方案 |
|--------|--------|
| resp 全局峰值抠模板 + 全图匹配 | **无模板**；规则网格 + 每格 top-hat |
| 易误检边框反光 | 亮框内缩 ROI + 格内局部对比 |
| 依赖 `cali_board.shm` Find + Mask | 已自 v4 flow 移除 |
